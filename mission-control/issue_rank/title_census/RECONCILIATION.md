# Reconciling the title census into `title_taxonomy.py`

`../title_taxonomy.py` (#927) is the single owner of title parsing (AGENTS.md L4). The census in this
folder was built independently the same day, before the overlap was found. This document lists what
the census adds and how each piece maps onto the owner, so it can be merged in without a second parser.
Nothing below is implemented in `title_taxonomy.py` by this PR.

## Structure

| Census concept | `title_taxonomy.py` equivalent | Proposed reconciliation |
|---|---|---|
| `type` (12, incl. `plan`) and `type_family` (change, defect, knowledge, pipeline, quality, maintenance, planning) | `ACTIONS` (`family` in `parse_title` output) | Add the missing action aliases in the types table below; keep the owner's extra actions (`metrics`, `security`, `governance`, `release`, `source`, `triage`, `program`); add a type-family grouping as a derived field |
| `family` › `scope` (26 families, 67 scopes, aliases; `=alias` only matches in an explicit prefix) | `TOPIC_FAMILIES`, `TECHNICAL_CLUSTERS`, `PROGRAMS` | Add the uncovered scopes and missing aliases (tables below); keep the census's explicit-only rule for generic words (`green`, `gate`, `dock`, `cp`, ...) to avoid false matches |
| Qualifier classes: wave `W327`, pulse `N12`/`N16–N18`, jade step `J14`, gate `G3C`, user ticket `U6`, priority/phase `P0`/`P3R`, fleet `F01`, round `R3`, version, program `GM14`, ticket `GOV-001`, PR ref, rank | `codes`, `RANGE`, `priority` | Port the qualifier patterns that `CODE`/`RANGE` do not match yet |
| Lead labels without conventional syntax: `W327: ...`, `CBD W4: ...`, `MissionControl: ...`, `RFI-QPS-CC-01: ...`, `Feature/dow integration` | `_frontmatter`, `leading_code` / `leading_clause` tags | Add these cases to `test_title_taxonomy.py` first; they make up a large share of cryoplant and ABACUS titles |
| Evidence source per field: `title`, `lead`, `label`, `branch`, `pr#N`, `keyword`, `parent#N`, `children`, and confidence `explicit` / `strong` / `inferred` / `none` | `classification` (`EXPLICIT_ACTION` / `CODES_ONLY` / `UNCLASSIFIED`), recursive family candidates | Keep the owner's rule: linked candidates never overwrite. Add closing-PR evidence (`closedByPullRequestsReferences`) as a candidate source |
| Lint T001–T011 | `lint` warnings | Map codes one to one; T007 (scope used as type) and T011 (freeform lead label) are the most frequent in the census |
| Per level: n, share, rank, open/closed/merged, 30-day trend, median days to close, monthly running totals; spread stats (keys, mean, median, P90, max, top-5 share, tail share, Gini) | `summary()` per repo / JADE / USER | Add these metrics to `summary()` output and render the dashboard from it |
| PR / issue crosswalk edges, one per pair with merged evidence: `closes` (both sides, body keywords, closing cross-references), `parent`, title `mentions`, body `refs`, timeline `xref`; per-family crosswalk and family-to-family link counts | `build_graph()` and `associated_families()` (typed reference graph, max two hops) | Feed `closingIssuesReferences` / `closedByPullRequestsReferences` with repo names into `build_graph()`; keep PageRank / betweenness there; add the per-family crosswalk counts to `summary()` |
| Link-voted candidate family for titles with none (`link_family`, `link_share`, `link_status`) | linked family candidates in `associated_families()` (never overwrite) | Same rule; the census adds type weights (closes/parent 3, title 2, body/timeline 1) and a 60% clear threshold that can be ported |
| Per-family CI view in three lenses (default branch per check weighted by DevOps-census test jobs; PR-head code checks with always-red gates set apart and a Wilson-bound rank; combined state), checks with DAG / SIPOC / OID binding, activity signatures | `red_trace.classify()`, `cicd_dag.everred_metrics()`, `RED_TRACE_FEDERATION_N8.json`, `site/cicd_dag_crosswalk.csv` (used as is) | Nothing to port: the census only groups by family. If kept, a per-family lens belongs next to `everred_metrics()` as its own owner decision |
| Lossless retitle suggestion and snapshot-guarded `apply_issues.py` | none: #927 forbids renames | Keep it out of the owner; any future rename tool needs its own owner decision |
