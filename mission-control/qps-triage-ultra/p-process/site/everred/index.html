Addendum to the standard · where EVERRED 2.0 needed detail

A1Occurrence and signature

An occurrence is one failed step in one job run: repo, SHA, PR, workflow, job, step, run ID and attempt, job ID, runner, completion time. The signature is workflow :: job :: step with OS and Python moved to the environment, hashes replaced by <sha> and worker sequence numbers by *. Upgrade path: JUnit test IDs and scanner rule IDs as a fourth signature level.

A2Root IDs and ledger

<REPO>-RC-YYYY-NNNN (V3; V2 EVR-… IDs stay as aliases), never reused; a split creates new IDs with split_from, a merge keeps the older ID. The ledger lives in the owning repo (proposed governance/everred/roots.yaml) and exports to CODEX as a REX return (gbogeb-repo-rex-return/1.0, merge key = signature), so the CODEX #989 rule "update the existing record before minting" applies unchanged.

A3New class: control-plane drift

Rulesets, branch protection, required-check names or app IDs that differ from the declared policy. Detected by a probe each census, not by a failing job, because a missing gate produces no red at all. Fail-closed; owner-only repair. First instance: EVR-ABACUS-0001.

A4Aggregators and umbrella steps

Jobs that only summarise other reds (Full Red Proof Summary) are derived and never counted as roots. Enforce steps that combine several tools (security: Bandit + Safety; quality: Black + isort + Flake8) are umbrella signatures; split them into one root per tool from the upstream step outcomes before assigning owners.

A5One lane per root

  • Branch everred/<root-id>-<slug>, draft PR labelled everred:<root-id>.
  • The ledger's owner plus the open lane PR is the lock.
  • A second worker whose failure matches the signature comments on the lane PR and links its occurrence; it does not open a competing fix.

A6Who may move a root

  • Agent: DISCOVERED → TRIAGED → FIX_COMMITTED → PRODUCER_GREEN → CONSUMERS_REPLAYED, each with a linked run.
  • Owner: OWNED, any BLOCKED_AUTHORITY decision, policy dispositions.
  • Independent reviewer: VERIFIED_FIXED for security roots.
  • CLOSED only after the observation window passes with no matching occurrence.

A7Metrics as implemented

  • Amplification = occurrences on triaged independent roots ÷ triaged independent roots.
  • Signature amplification (occurrences ÷ distinct signatures) is shown as an upper bound only.
  • Replay coverage stays UNKNOWN until replay outcomes are recorded per consumer.
  • No metric ever reports 0 for a missing denominator.

A8EVERRED and Code Purple

Code Purple is the acute response to an admission deadlock, with lift criteria. EVERRED is the standing root system. Code Purple's close-out hands its inherited reds to EVERRED as roots; EVERRED escalates to Code Purple when a root blocks all admission or a control-plane probe turns red. Lesson from this run: break glass with a bypass actor, never by deleting rules, and verify rule content in the lift check.

A9Cadence and receipts

Run the harvest each pulse and on a schedule; keep every everred.json as a dated, immutable census row. A later occurrence matching a VERIFIED_FIXED or CLOSED root reopens it automatically as a candidate.

A10Known limits of this census

  • Job logs and artifacts sit on a blob host this session cannot read, so causes come from step outcomes, annotations and local reproduction. A harvest running inside GitHub Actions can read the logs.
  • Consumer replay outcomes are not yet recorded.
