# JADE_CASTE — Executable stop/pivot/retrigger contract v2

SSOT: `data/STOP_MODEL_NPLUS2.json` (immutable input; frozen N+2 snapshot). Current pulse: `data/STOP_MODEL_N10.json`, which binds every gate to an exact-head receipt in `gate_receipts`, with its controller replay in `data/STOP_RECEIPT_N10.json`. A new pulse is a new file, never an edit to an older one; engine: `tools/stop_rules.py`, whose default `--model` is the current pulse (`python tools/stop_rules.py` replays `data/STOP_RECEIPT_N10.json`; pass `--model data/STOP_MODEL_NPLUS2.json` to replay the frozen N+2 snapshot, and move the default when a newer pulse lands). The controller checks every gate state against its `gate_receipts` entry before evaluating: the receipt state must equal the gate state, a `PASS` or waiver must cite `https://github.com/` evidence bound to the current exact head (the blocked RED canary and the required-checks ruleset read-back are the only gates whose evidence may sit on another commit or none), and any disagreement fails closed. A snapshot without `gate_receipts` counts its `PASS` gates as `UNKNOWN`, so it can never reach `TARGET_MET_STOP_ENGINEERING`; HTML: `site/burndown.html` (derived projection); native QA: `tests/test_stop_rules.py`. Every pulse must declare cohort Git blob, 21 eligible source heads, denominator, instrumentor version, exact-native run/job/attempt and all independent gate values. A count without a current-head trusted receipt is `null`.

## States, precedence and exits

| Order | Predicate | Result | Required follow-up |
|---|---|---|---|
| 1 | Current SHA has an owner-bound failed native source gate | `REPAIR_FIRST_RED` | Fix owner source, do not suppress test or re-label root |
| 2 | Same exact head native jobs pending | `WAIT_NATIVE` | Await terminal run and inspect job-level first-red; zero redundant dispatch |
| 3 | Independent reviewer, governance checks, blocked RED canary or security are missing/failed | `OWNER_BLOCKED` | Admin/reviewer action, server-side negative proof |
| 4 | Three consecutive equal matched terminal evidence pulses, 0 pending roots, all four numerical progress measures unchanged | `PIVOT_DISJOINT_OWNER` | Halt same recensus; seek different source owner or failure frontier |
| 5 | All nine gate states `PASS`, two *distinct* successful SHA/run IDs, no red/pending | `TARGET_MET_STOP_ENGINEERING` | Stop engineering repetition; separate authorized release decision required |
| else | Unqualified/unknown/noncomparable observation | `CONTINUE_DISJOINT_MEASUREMENT` | Qualify missing receipts without fabricated gain |

Nine noncompensating gates: source integrity, native tests, matched coverage, security, independent reviewer, required checks, blocked RED canary, hosted parity, owner release.

**Solo-owner review waiver (MACH-II).** A single-developer repo has no independent reviewer, so `independent_review` may be `WAIVED_MACH_II` (ABACUS `docs/governance/CODE_PURPLE_MACH_LADDER.md`). The model must then carry a `review_waiver` record (`level: MACH-II`, a `https://github.com/` `policy` link, and an `automated_review` of kind `copilot_review` or `codeql` with `head_sha` equal to the current exact head and a `https://github.com/` `url`). The waiver counts as PASS only while `required_checks` is `PASS`, which means the platform enforces them. Otherwise it counts as `MISSING` and the result is `OWNER_BLOCKED`. The waiver replaces that one gate only. No other gate accepts it. A flag without a record, or a record without the flag, fails closed. Receipts produced with a waiver carry `review_basis` (`WAIVED_MACH_II` or `WAIVER_UNQUALIFIED`), and receipts produced without one keep their exact previous shape. The presence of `NULL` or `UNKNOWN` is *not* a numerical zero or a PASS. Scope/head drift, different branch instrumentation, a partial source list and an owner-unknown decision disqualify plateau and release.

Pass no more than 12 hosted HTTP retries and two-or-three verification rounds to the sanctioned origin; use no second Pages publisher, browser token, background worker or silent postmerge normalization. The controller never mutates GitHub. All releases and merges remain gated by actual server-side rules.
