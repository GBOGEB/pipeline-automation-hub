## Mission / acceptance

Bring an approved subset, eventually the Mission Control mission-selected Top21, to **release-candidate readiness** for the next owner-defined point release. The project is an additive presentation/process programme, not a global release controller. **J4 qualified** means an owner can evaluate the point-release candidate. **J5 admitted** requires a real owner-approved release and cannot be granted by this dashboard.

## Distinct named programme assets

- `CODE PURPLE`: global quality, evidence, governance; `EVERRED`: root/failure census; `GoGREEN`: positive merge/run lineage; `CBD!`: blocker burndown.
- `JADE_TEMPLE`: chat continuity, shared instructions, human review artifacts and project navigation.
- `JADE_CASTE`: local repository readiness ladder and non-breaking convergence.
- Mission Control `TOP21_COHORT_ROSTER.json` and `REPO_CENSUS_ROLLUP_N11.json` remain the portfolio authority/dated inventory. ABACUS `TOP21_ROLLOUT_CONTRACT.md` remains separate five-candidate ranking scope.

21 source-bound repo identity cards; one documented repository landing contract; root/folder SPINE; applicability-qualified machine manifests; hosted HTML verification; evidence-bound governance tier proposal; minimally actionable issue/BD queue; DoD/DoV/admission status; version/readiness gaps; disjoint owner PR plan; recursive handover. Accept 21 distinct repo records, not 21 green claims.

## Exclusions at J0

No automatic repo renames or file moves, no force-push, no change of protected server rules, no owner transfer, no new global SSOT, no merge authorization, no fake hosted page or release publication, no replacement of ABACUS N+2 dashboard or QPS engineering disposition.
